# Подготовка стенда (чеклист, выполняется когда освободится память)

Порядок важен: каждый шаг проверяемый, не идём дальше, пока предыдущий не дал
ожидаемого вывода. Все пункты - на этом хосте: Windows 11, Ryzen 5600X,
32 ГБ, WSL2.

## 0. Что уже проверено

- `/dev/kvm` внутри WSL2 **есть**, флаг `svm` в `/proc/cpuinfo` прокинут.
  Вложенная виртуализация на AMD работает - главный риск снят.
- Ядро WSL2: `5.15.167.4-microsoft-standard-WSL2`.
- Свободно под образы: диск F: ~480 ГБ.

## 1. Освободить память

Fusion360 держит ~14 ГБ. Фабрике нужно 15 ГБ + накладные. Закрыть Fusion,
Astra-ВМ не поднимать одновременно со стендом.

## 2. Поднять лимиты WSL2

WSL2 по умолчанию берёт половину хоста (16 ГБ) - этого на 3 узла по 5 ГБ
не хватит. Создать `C:\Users\user\.wslconfig`:

```ini
[wsl2]
memory=26GB
processors=12
nestedVirtualization=true
```

Затем `wsl --shutdown` и проверить внутри: `free -g`, `nproc`, `ls -l /dev/kvm`.

## 3. Нормальный дистрибутив вместо docker-desktop

Сейчас в WSL только служебный `docker-desktop`. containerlab хочет privileged,
правит network namespace и ставит системные пакеты - ему нужен обычный
дистрибутив и нативный докер, Docker Desktop тут помеха.

```bash
wsl --install -d Ubuntu-24.04
```

Внутри: docker-ce из официального репозитория (не Docker Desktop), затем
containerlab штатным установочным скриптом. Проверка: `docker run hello-world`
и `containerlab version`.

## 4. Образ vJunos

Скачивает пользователь сам, под своим аккаунтом:

- бесплатный аккаунт на support.juniper.net, лицензия не нужна, ограничения
  по времени нет;
- файл - `vJunos-switch` qcow2, ~4-5 ГБ, версию зафиксировать и записать
  в README;
- положить в WSL, собрать докер-образ через vrnetlab (`make` в каталоге
  соответствующего узла), имя образа сверить с `topology/evpn-fabric.clab.yml`.

Образ в репозиторий не кладём - только имя и версия.

## 5. Первый запуск - два узла, не три

Не поднимать сразу всю фабрику. Сначала два узла и линк между ними: цель -
убедиться, что тулчейн живой и узел грузится. Замерить время загрузки
(ожидается несколько минут) и проверить, что containerlab не отваливается
по таймауту готовности.

```bash
containerlab deploy -t topology/two-node-smoke.clab.yml
```

(файл smoke-топологии напишу, когда дойдём до этого шага)

## 6. Дальше

Underlay eBGP -> overlay EVPN -> VXLAN -> счастливый путь -> скрипт замера ->
матрица отказов. Каждый шаг даёт либо конфиг в `configs/`, либо запись
в раздел «Грабли».

## Правка от 10.10.2026: образ сменился

Пункт 4 выше устарел. Качаем **не vJunos-switch, а cJunosEvolved**:
https://support.juniper.net/support/downloads/?p=cjunos-evolved

Причина: у vJunos-switch в требованиях Intel VT-x и прямой запрет на запуск
изнутри ВМ из-за глубокой вложенности (архитектура vMX, VCP+VFP уже вложены).
WSL2 - это ВМ. У cJunosEvolved в требованиях прямо указан AMD и поддержка
containerlab.

Что меняется по шагам:

- **Памяти больше:** 8 ГБ на узел вместо 5, три узла = 24 ГБ. В `.wslconfig`
  ставим `memory=26GB`. Fusion и Astra-ВМ при этом погашены.
- **Диск:** 20 ГБ на контейнер в рантайме, до 40 ГБ. Три узла - закладываем
  ~120 ГБ. Диск C: сейчас 128 ГБ свободно, это впритык: WSL-дистрибутив
  лучше вынести на F: (`wsl --export` / `--import` в каталог на F:).
- **Докер строго >= 28.0.0.** В доке Juniper предупреждение: на более старых
  версиях интерфейсы подключаются к контейнеру не в том порядке, и трафик
  между узлами не идёт. Отказ при этом немой - проверить `docker version`
  до первого запуска, а не после.
- **vrnetlab не нужен.** cJunosEvolved - уже контейнер, шага со сборкой
  образа из qcow2 нет. Образ загружается напрямую (`docker load`).
